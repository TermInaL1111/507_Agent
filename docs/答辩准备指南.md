### 二、技术栈讲解

**评委想看**：你为什么选这些技术，不是随便写的。

**你要准备的**：

1. **一句话总览**：
   > "前端 Vue3，后端 FastAPI + Django 双服务，模型 DeepSeek V3，
   > 向量库 ChromaDB，部署 Docker Compose 5 容器。"

2. **每个选择的理由**：

| 技术 | 为什么选 |
|------|----------|
| Vue3 + Element Plus | 生态成熟，组件丰富，SSE 实时流式方便 |
| FastAPI | 异步原生支持，SSE 流式响应，自动生成 OpenAPI 文档 |
| Django | 用户认证体系成熟，DRF + SimpleJWT 开箱即用 |
| DeepSeek V3 | 性价比高（免费额度），中文理解好，OpenAI 兼容 API |
| LangChain | Agent 工具注册/调度标准化，18 个 @tool 快速扩展 |
| ChromaDB | 轻量级，零配置，嵌入式部署，适合学生项目 |
| Docker Compose | 5 个服务一键构建部署，环境一致性保障 |

3. **文档支撑**：
   - `CLAUDE.md` — 架构速查
   - PPT Slide 3,5,7 — 技术栈/设计决策/部署视图

3. **可能被问到的扩展性问题 + 回答**：

| 问题 | 回答思路 |
|------|----------|
| "为什么不用 LangGraph？" | 当前场景 Agent 单次调用已满足，LangGraph 适合复杂多步工作流，是后续扩展方向 |
| "向量库为什么选 ChromaDB？" | 学生项目轻量首选，零配置嵌入部署；生产环境可换 Milvus/Qdrant |
| "Agent 工具选择准确率 100% 怎么做到的？" | System Prompt 明确场景指引 + 工具 description 优化 + DeepSeek V3 function calling 能力强 |
| "用户数据安全怎么保证？" | JWT 鉴权 + 会话归属校验 + 令牌黑名单 + 知识库分集合隔离 |
| "如果 500 人同时用怎么办？" | 当前 Redis 限流 + Docker 可横向扩展 FastAPI 实例 + Nginx 负载均衡 |
| "敏捷方法的局限性？" | Solo 开发场景的 Pair Programming/集体所有权难以落地；通过 Code Review + 自动化测试弥补 |
